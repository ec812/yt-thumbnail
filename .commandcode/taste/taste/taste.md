# Taste
- Keeps implementation plans as dated markdown files (seen under `docs/plans/` and `.hermes/plans/`, named like `2026-09-18_161500-save-load-project.md`) containing complete copy-pasteable code for each function, and expects the agent to read the plan and implement all enumerated tasks in the given order. Kicks this off with a single terse, autonomous-mode instruction rather than interactive back-and-forth. Confidence: 0.65
- For client-side persistence in browser tools, explicitly asks for `localStorage` with the state serialized as a simple array (fixed field order) rather than a keyed object or server-side storage. Confidence: 0.5
- Prefers self-contained single-file deliverables for small web tools — one `index.html` with embedded CSS and JS rather than split files or a build step. Confidence: 0.65
- Prefers dark UI styling for the apps/tools they request. Confidence: 0.6
- Wants git work scoped to a local `git init` + commit by default; publishing (creating a public repo, enabling Pages, pushing) should only happen when explicitly asked. Expects each completed feature to be committed to git as part of the task — often ending a request with an explicit "git commit when done". Confidence: 0.6
- Expects feature additions to be additive and non-breaking — repeatedly asks that new controls work with the existing ones and that all existing functionality keep working, so extend with targeted edits rather than rewriting the file. Confidence: 0.65
- Wants controls/options to be consistent across object types in the same tool — when image layers need styling, expects them to expose the same control set as text layers (stroke width/color, shadow X/Y/blur/color) rather than a bespoke subset. Confidence: 0.5
- Makes their own manual edits to the project files between agent runs and expects them preserved — explicitly calls out existing changes (e.g. a CSS overflow fix) to keep intact and does not want unrelated/touched-upon work reverted or bundled away. Confidence: 0.55
- Reports UI/visual defects by attaching an annotated screenshot of the broken state and expects the agent to read the image, identify the visual cause (e.g. a clipped slider thumb), and fix that instead of guessing; also expects visual verification of the fix, not just passing tests. Confidence: 0.55
- Separates commit policy by request type: feature work ends with a commit, but a targeted bug-fix request may come with an explicit "not git commit" and then the change must stay uncommitted in the working tree. Confidence: 0.5
- Prefers web fonts loaded from the Google Fonts CDN (with preconnect links) and pinned via a single font-family constant, rather than bundling font files or relying on system fonts. Confidence: 0.5
- Expects cross-cutting features to apply uniformly to every user-facing control, not just a subset — e.g. calls it a defect when undo/redo covers structural actions but not slider or color-picker edits, rather than accepting the narrower scope. Confidence: 0.5
