# Taste
- Keeps implementation plans as dated markdown files (seen under `docs/plans/` and `.hermes/plans/`, named like `2026-09-18_161500-save-load-project.md`) containing complete copy-pasteable code for each function, and expects the agent to read the plan and implement all enumerated tasks in the given order. Kicks this off with a single terse, autonomous-mode instruction rather than interactive back-and-forth. Confidence: 0.65
- For client-side persistence in browser tools, explicitly asks for `localStorage` with the state serialized as a simple array (fixed field order) rather than a keyed object or server-side storage. Confidence: 0.5
- Prefers self-contained single-file deliverables for small web tools — one `index.html` with embedded CSS and JS rather than split files or a build step. Confidence: 0.65
- Prefers dark UI styling for the apps/tools they request. Confidence: 0.6
- Wants git work scoped to a local `git init` + commit by default; publishing (creating a public repo, enabling Pages, pushing) should only happen when explicitly asked. Expects each completed feature to be committed to git as part of the task — often ending a request with an explicit "git commit when done". Confidence: 0.6
- Expects feature additions to be additive and non-breaking — repeatedly asks that new controls work with the existing ones and that all existing functionality keep working, so extend with targeted edits rather than rewriting the file. This includes control *interactions*: a newly added control must not silently break existing ones when used together (e.g. enabling a new clip/crop mask must keep stroke and shadow rendering correctly on the same layer). Confidence: 0.7
- Wants controls/options to be consistent across object types in the same tool — when image layers need styling, expects them to expose the same control set as text layers (stroke width/color, shadow X/Y/blur/color) rather than a bespoke subset; likewise, when a new layer type gains controls (opacity, blending mode), explicitly asks that existing layer types' inspectors be updated to expose them too. Confidence: 0.6
- Makes their own manual edits to the project files between agent runs and expects them preserved — explicitly calls out existing changes (e.g. a CSS overflow fix) to keep intact and does not want unrelated/touched-upon work reverted or bundled away. Confidence: 0.55
- Reports UI/visual defects by attaching an annotated screenshot of the broken state and expects the agent to read the image, identify the visual cause (e.g. a clipped slider thumb), and fix that instead of guessing; also expects visual verification of the fix, not just passing tests. Confidence: 0.55
- Separates commit policy by request type: feature work ends with a commit, but a targeted bug-fix request may come with an explicit "not git commit" and then the change must stay uncommitted in the working tree. Confidence: 0.5
- Prefers web fonts loaded from the Google Fonts CDN (with preconnect links) and pinned via a single font-family constant, rather than bundling font files or relying on system fonts. Confidence: 0.5
- Expects cross-cutting features to apply uniformly to every user-facing control, not just a subset — e.g. calls it a defect when undo/redo covers structural actions but not slider or color-picker edits, rather than accepting the narrower scope. Confidence: 0.5
- Writes fully-specified feature requests: an exhaustive enumeration of options/labels plus their underlying primitive values (Photoshop blend-mode names mapped to canvas `globalCompositeOperation` strings, clip-shape names mapped to their internal values), given in a specific order, with per-option behavioral rules — and expects verbatim fidelity to that list. Confidence: 0.6
- Expects visual transforms to be non-destructive: clipping/cropping must be applied at render time (e.g. as a canvas clip path before drawing) rather than baked into the underlying image data, so reverting the setting restores the original image. Confidence: 0.6
- Wants a single consistent positioning/interaction model across all movable layer types: text should use the same X/Y pixel-offset-from-center model as image layers rather than a bespoke control, and expects every movable layer type to be draggable directly on the canvas with the inspector sliders tracking the drag live. Confidence: 0.6
- Treats limited single-purpose abstractions as mistakes to be replaced, not extended — when an existing control only covers part of a need (e.g. a percentage "Vertical position" slider), prefers swapping it out for a general, direct-value model over layering new controls on top of the old one, and will call the old approach "premature". Confidence: 0.5
- Expects familiar design-tool keyboard modifiers on canvas interactions — holding Shift while dragging a layer should constrain the drag to a single axis, and reports the missing/odd behavior as a defect rather than an acceptable limitation. Confidence: 0.45
- Expects standard design-tool panel conventions rather than bespoke controls — e.g. double-clicking a row in the layers list should start an inline rename, and the affordance must work for every row type (text, color, image filename) uniformly. Confidence: 0.45
- Expects canvas state to speak the familiar image-editor visual language — e.g. when nothing is visible (all layers toggled off) the canvas should show a tiled alpha-checkerboard backdrop (Photoshop-style, repeating in both x and y) instead of a blank/solid fill. Confidence: 0.45
- Uses Photoshop as the reference for how rendered output should look and size, and flags apparent divergence as a defect ("did you stretch the tiles? They look larger than they looked in photoshop") — so preview affordances/guides should render at their native, fixed on-screen size rather than magnifying with the preview scale, and stay out of exported images. Confidence: 0.5
